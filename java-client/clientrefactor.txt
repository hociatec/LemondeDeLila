│ TÂCHE 1.1: Créer WebSocketConnectionFactory<T> abstrait                │
└─────────────────────────────────────────────────────────────────────────┘

Nouveau fichier:
framework-network/src/main/java/com/lemondelila/client/framework/network/factory/AbstractWebSocketConnectionFactory.java

Contenu:
```java
public abstract class AbstractWebSocketConnectionFactory<T extends AutoCloseable> {
    protected final HttpClient httpClient;
    protected final ObjectMapper objectMapper;
    protected final NetworkEndpoints endpoints;
    protected final ClientSession session;

    protected AbstractWebSocketConnectionFactory(
        HttpClient httpClient,
        ObjectMapper objectMapper,
        NetworkEndpoints endpoints,
        ClientSession session
    ) {
        this.httpClient = httpClient;
        this.objectMapper = objectMapper;
        this.endpoints = endpoints;
        this.session = session;
    }

    protected String resolveToken() throws AuthenticationRequiredException {
        if (session.getAuth() == null) {
            throw new AuthenticationRequiredException();
        }
        return session.getAuth().getAccessToken();
    }

    protected URI appendToken(URI uri, String token) {
        // Logique extraite des factories existantes
    }

    public abstract T createConnection() throws Exception;
}
```

Modifications:
- ChatConnectionFactory extends AbstractWebSocketConnectionFactory<ChatConnection>
- NotificationConnectionFactory extends AbstractWebSocketConnectionFactory<NotificationConnection>
- PresenceConnectionFactory extends AbstractWebSocketConnectionFactory<PresenceConnection>

Chaque factory conserve uniquement:
- La méthode createConnection() spécifique
- La résolution d'endpoint spécifique

Compatibilité: ✓ PRÉSERVÉE (signature publique identique)
Tests requis: Valider que chaque factory fonctionne toujours

Nouveau fichier:

Contenu:
```java
public final class JsonNodeUtils {
    private JsonNodeUtils() {}

    public static Optional<JsonNode> asObject(JsonNode node) {
        return node != null && node.isObject()
            ? Optional.of(node)
            : Optional.empty();
    }

    public static Optional<String> asText(JsonNode node) {
        return node != null && node.isTextual()
            ? Optional.of(node.asText())
            : Optional.empty();
    }

    // Autres helpers...
}
```

Remplacement progressif dans:
- RoomRealtimeService
- RoomInviteNotificationService
- GameRealtimeClient
- Etc.

Pattern actuel:
```java
if (!node.isObject()) return null;
JsonNode field = node.get("field");
```

Nouveau pattern:
```java
return JsonNodeUtils.asObject(node)
    .flatMap(n -> JsonNodeUtils.asText(n.get("field")))
    .orElse(null);
```

Compatibilité: ✓ PRÉSERVÉE (refactoring interne uniquement)

│ TÂCHE 2.1: Décomposer RoomRealtimeService                              │
└─────────────────────────────────────────────────────────────────────────┘

Fichier actuel:
client-app/src/main/java/com/lemondelila/client/game/room/service/RoomRealtimeService.java (302 lignes)

Responsabilités actuelles:
1. Gestion lifecycle WebSocket (connect, disconnect, reconnect)
2. Parsing JSON → événements (parseRoomStateUpdate, parseBotUpdate, etc.)
3. Publication d'événements via DomainEventBus
4. Gestion de l'état de connexion

Décomposition proposée:

A) Créer RoomEventParser
   Fichier: .../game/room/service/RoomEventParser.java
   Responsabilité: Parsing JSON → objets domaine
   Méthodes:
   - parseRoomStateUpdate(JsonNode) → Optional<RoomState>
   - parseBotUpdate(JsonNode) → Optional<BotUpdate>
   - parsePlayerUpdate(JsonNode) → Optional<PlayerUpdate>

B) Créer WebSocketChannelManager
   Fichier: framework-network/.../WebSocketChannelManager.java (réutilisable)
   Responsabilité: Lifecycle d'un channel WebSocket
   Méthodes:
   - connect(String channelId)
   - disconnect()
   - reconnect()
   - onMessage(Consumer<JsonNode>)
   - onConnectionState(Consumer<State>)

C) Refactorer RoomRealtimeService
   Nouveau rôle: Orchestrateur
   Dépendances:
   - WebSocketChannelManager (gestion connexion)
   - RoomEventParser (parsing)
   - DomainEventBus (publication)

   Simplifié à ~100 lignes:
   ```java
   public void connectToRoom(String roomId) {
       channelManager.connect(roomId);
       channelManager.onMessage(this::handleMessage);
   }

   private void handleMessage(JsonNode message) {
       parser.parseRoomStateUpdate(message)
           .ifPresent(state -> eventBus.publish(new RoomUpdated(state)));
       parser.parseBotUpdate(message)
           .ifPresent(bot -> eventBus.publish(new BotJoinedRoom(bot)));
       // etc.
   }
   ```

Compatibilité: ✓ PRÉSERVÉE (API publique de RoomRealtimeService identique)
Migration: Interne uniquement, pas de changement pour les appelants

================================================================================
STRATÉGIE DE MIGRATION SÉCURISÉE
================================================================================

PRINCIPES:
1. ✓ Interface-First: Créer abstractions avant de modifier les implémentations
2. ✓ Backward Compatibility: Toujours préserver les signatures publiques
3. ✓ Incremental: Une classe à la fois, valider avant de continuer
4. ✓ Test-Driven: Valider après chaque changement
5. ✓ Feature Branch: Ne pas merger avant validation complète

WORKFLOW PAR TÂCHE:
1. Créer nouvelle abstraction/utilitaire
2. Ajouter tests pour la nouvelle abstraction
3. Migrer UNE classe existante
4. Valider que cette classe fonctionne
5. Migrer les autres classes une par une
6. Supprimer le code dupliqué
7. Commit

GIT WORKFLOW:
- Chaque phase = une feature branch
- Phase 1: feature/refactor-phase1-utilities
- Phase 2: feature/refactor-phase2-services
- Phase 3: feature/refactor-phase3-quality
- Merge après validation complète
