# Navigation complète de l’Admin

## Principe

Toute l’administration fonctionne dans **un seul écran/conteneur**.

Quand l’utilisateur ouvre une rubrique, on remplace le contenu courant par le sous-écran correspondant. On ne crée pas une nouvelle fenêtre.

Navigation générale :

```text
Admin
→ rubrique
→ liste
→ élément
→ actions
→ formulaire éventuel
```

`Échap` revient au niveau précédent.

# 3. Gérer les jeux

```text

→ Gérer les jeux
→ Liste des jeux
```

Sélectionner un jeu ouvre :

```text
Jeu : [nom]

├─ Activer / Désactiver
├─ Activer / Désactiver le chat en table
├─ Activer / Désactiver les sons du chat
├─ Modifier le statut
├─ Modifier le nom
├─ Modifier la description
├─ Règles du jeu
├─ Attribuer une catégorie
├─ Gérer le quiz Mnémosyne (si disponible)
├─ Modifier min/max joueurs
└─ Réinitialiser les paramètres
```

Les modifications de nom, description, règles ou statut ouvrent un formulaire puis :

```text
→ Valider
→ retour au jeu / liste
```

Min/max joueurs ouvre également un formulaire dédié.

# 19. Organisation technique à reproduire

Le développeur doit penser l'ensemble comme une machine à états/navigation :

```text
AdminScreen
│
├─ page courante
├─ titre
├─ liste d'items
├─ élément sélectionné
├─ champs de formulaire éventuels
├─ détails éventuels
└─ écran parent
```

Les composants nécessaires sont principalement :

```text
AdminShell
├─ Title
├─ Menu/List
├─ Form
├─ Filters
├─ Details
└─ SpecialContent
```

Un changement d'écran revient donc essentiellement à faire :

```text
page = USERS
title = "Gestion des utilisateurs"
items = utilisateurs
filters = userFilters
```

puis :

```text
page = USER_ACTIONS
title = "Utilisateur : Jean"
items = actionsUtilisateur
filters = null
```

Il ne faut **pas recréer une fenêtre** à chaque étape.

Actions :

Aperçu

Changer
→ ouvre un sélecteur de fichier
→ accepte .wav / .wave / .mp3
→ remplace le son

Le développeur doit donc créer un seul écran SoundDetails réutilisable, pas une fiche différente pour chaque son.
